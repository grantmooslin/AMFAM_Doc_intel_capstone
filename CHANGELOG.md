- **Data-backed prompt enhancement list** — `docs/experiments/prompt_enhancement_list.md` synthesizes the Monte Carlo suite into a prioritized enhancement set. Key data: committee voting is a weak lever (K=1→10: 82.1%→85.3%); 27.7% of current-line misses are near-misses (recoverable +3.9pp to 89.9%); confidence-gated escalation of the bottom 10–15% buys +4–6pp at +20–30% cost; `--fallback-model` cuts simulated failure rate ~24x (2.86% → 0.114%); v16 vs v17 is a statistical tie on shared images (P=0.565); `form` is the top false-prediction attractor (5 of top 8 confusion pairs end in form).
- **Prompt `v18` (EXPERIMENTAL, not default, verification did NOT confirm)** — v17.2 + four Monte Carlo-mined exemplar appendix entries (letter vs memo, MSDS specification vs form, PHS 398 resume vs form, survey questionnaire vs form), each a correct trace whose runner-up named the decoy. Measured on the exemplar slice (48 images): **v18 64.6% vs v17.2 68.8% (−4.2pp)** — the exemplar text did not help and slightly hurt. The negative result is itself a finding: more exemplar text does not fix the runner-up-vs-final decision; a decision rule is the next experiment. Retained for reference, not promoted.
- **`monte_carlo_verify_compare.py`** — compares `mc_verify_*` eval manifests against the simulator's predictions (simulated p_correct vs measured on the escalation slice; v17.2 vs v18 paired flips on the exemplar slice). Zero spend.
- **Verification evals (`monte_carlo_verify.py --run-eval`)** — 4 targeted 48-image evals. Escalation tail: base 66.7%, same-model max-effort 62.5% (confirms the tail is hard — well below the 82% average — and that a stronger model, not more effort, is required for escalation). Exemplar slice: v17.2 68.8% vs v18 64.6%.

### Changed

- **Monte Carlo simulation over the eval corpus** — new `monte_carlo_*` toolchain that treats every completed eval row as a sample from a per-image label distribution and answers "what if" questions with zero API spend:
  - `monte_carlo_corpus.py` — builds the joint corpus (`reports/monte_carlo/corpus.jsonl`, 4,641 rows / 1,512 images) from all manifests, backfilling reasoning traces + `finish_reason`/`fallback` from Braintrust spans (read-only, no scorer credits).
  - `monte_carlo_ensemble.py` — committee-vote simulation (accuracy vs K with bootstrap CIs), per-image confidence heuristic, and confidence-gated escalation Pareto curve with a ±5pp sensitivity band + `escalation_candidates.txt`.
  - `monte_carlo_prompt_ablation.py` — paired-bootstrap prompt comparison on shared images: mean delta, 95% CI, `P(A wins)`, per-class deltas. Statistical gate for prompt promotion.
  - `monte_carlo_failures.py` — event-simulates the retry/failover/fallback pipeline from fitted probabilities; extrapolated failures + tail risk at 800/25K/320K and a `max_tries`×fallback sweep.
  - `monte_carlo_exemplars.py` — mines correct near-miss reasoning traces (runner-up names the decoy) as few-shot exemplars; MC random search selects a token-budgeted subset and emits a ready-to-paste exemplar appendix.
  - `monte_carlo_verify.py` — spend-minimal verification: builds the low-confidence escalation slice and a top-confusion-pair slice, prints the exact eval commands (dry-run default; `--run-eval` to spend).
  - `src/monte_carlo.py` — shared bootstrap / entropy / vote / confidence utilities; unit-tested in `tests/test_monte_carlo.py`.
  - Findings documented in `docs/experiments/monte_carlo_simulation.md`; artifacts in `reports/monte_carlo/`.
- **Key early results**: committee voting gains ≤4pp even at K=25 (variance budget is low); escalating the lowest-confidence ~10-15% to a ~90%-accurate model buys +4-6pp at +20-30% cost; the fallback-model pass cuts simulated failure rate ~25x (2.9% → 0.11%); v0→v17 is +28.4pp but v16 vs v17 is statistically inconclusive on shared images (P=0.57), and v11.8 still edges v17 (P=0.94).

### Changed

- **800-image `rvl_cdip_800` evaluation (new env)** — qwen3.7-flash on 800 images (50/class × 16): **v0 529/800 (66.1%)**, **v11.8 665/800 (83.1%)**. v11.8 gains +17.0pp over the v0 baseline on the same 800-image slice. v0 cost $0.1792 expected / $0.1773 actual (+1.1%); v11.8 $0.3276 expected / $0.3427 actual (+4.6%, heavy prompt caching — ~61% of prompt tokens cached at 10%). v11.8 top confused pairs: budget→invoice (13), letter→memo (10), invoice→budget (7). Reports + confusion matrices in `reports/` (`experiment_reports/`, `confusion_matrices/`, `failed_reasoning_traces/`).
- **v0 baseline prompt evaluation** — added `PROMPT_V0` (915-char function-not-subject-matter baseline, no check structure) and ran it on the 480-image `fixed_size_sampled_480` slice with qwen3.7-flash: **69.2%** (332/480) exact_match, 0 failed rows, expected cost $0.085 vs actual $0.0846 (+0.5%). Strongest classes: memo 100%, advertisement/email/scientific_publication 93%. Weakest: presentation 37%, budget 43%. Provides a control point for measuring prompt-engineering gains over the v17.x line.
- **New Braintrust environment migration** — project moved to `AMFAMv2` (org `4cb7718c-...`, project_id `9e76bd46-...`). `copy_datasets_to_new_env.py` re-uploads dataset slices with sync attachment upload + 8 retries (S3 PUTs are intermittently flaky). `.env` still carries the old key; scripts must use `config.api_key` from `load_braintrust_config()` (new key).
- **v17.2 three-slice generalization** — two new counter-example worked examples (invoice with form layout → invoice, newspaper page with embedded ad → news_article) and two calibration sentences (form-is-never-a-default, presentation vs memo slide-style). The 4 redundant v11.9 worked examples (questionnaire, scientific_report, scientific_publication, estimate-change-order) were stripped from the v17 base — they redundantly teach rules already explicit in the check structure and contributed to v16's 81.6 % accuracy. Sourced from v17.1 v1+v2+v3 multi-slice analysis (53 failures across 480 images, ~89 %). Four counter-examples total, all teaching overrides the raw check structure doesn't encode. 46,870 chars (+2,216 vs v17.1; -4,883 vs v16, -9.4 %). v17.2 is now the default prompt.
- **v17.1 surgical enhancements** — two worked examples (handwritten letter → handwritten, agency estimate → budget) and two calibration sentences added. Sourced from v16 v2+v3 analysis (81.6 %). v16's worked examples actively taught the wrong behavior; the replacements reverse that guidance.
- **Truncated-response salvage** — the eval retry loop now calls `extract_prediction()` on every response BEFORE checking `finish_reason`. Truncated (`finish_reason=length`) and provider-errored (`finish_reason=error`) responses often still contain a valid classification label; this rescue recovers the ~10 % of samples that were previously discarded as evaluation failures after exhausting all retries.
- **`finish_reason` logged in Braintrust metadata** — every successful row now records its API `finish_reason` in the span metadata so salvaged predictions can be identified and audited.
- **v17 prompt now default** — replaces v16 with a streamlined v11.9 derivative that removes the agency-estimate sub-protocol from check-7 (budget/invoice) and adds an explicit LETTER/MEMO OVERRIDE in check-2 (handwritten). Prompt is 4,627 chars lighter than v16 (46,277 vs 51,753), eliminating the finish_reason=length failures caused by qwen3.7-flash exhausting reasoning tokens on the bloated v11.9 check-7 section.
- **Reasoning effort reduced to `medium`** for qwen models (was `high`) to further cut token burn and eliminate `finish_reason=length` failures; 13 of 16 failed rows in v16 multispect were length-related.
- **MAX_TOKENS_CAP raised to 32,768** (was 16,384) as an additional safeguard against reasoning-token exhaustion.
- **Failed-row tracking** — errored rows now return an `ERROR:` sentinel output and are scored as both `exact_match` (miss) and a new tracked `failed` metric in Braintrust experiments.
- **HTTP timeout (300s)** added to the OpenAI client to prevent hung eval runs on stalled provider connections.
- **Manifest support** added to all eval launches for resumability after interruptions.

### Added

- **Manifest row tags (`OK` / `MISS!` / `ERROR!`)** — the eval runner stamps every manifest record with a `tag` (OK = correct, MISS! = wrong prediction, ERROR! = failed/empty) and prints `OK ` / `MISS!` / `ERROR!` labels in the per-image summary. `score_manifest.load_manifest()` derives the tag in-memory when absent, so pre-existing manifests still report tags; the 1120-image v11.8 manifest was rewritten with physical tags (1120 unique rows → 925 OK / 195 MISS! / 0 ERROR!).
- **`braintrust_report_manifest.py`** — manifest-first full report generator. Merges reasoning + metric traces from Braintrust experiments (matches the exact experiment name plus Braintrust's resume-loop version suffixes like `-06b91b68`) and writes `report_<exp>.md`, `per_class_accuracy_*.png`, `confusion_matrix_*.{png,md}`, `misclassification_reasoning_*.md` to `reports/`, appending a summary to `docs/experiments/experiment_log.md`. Reuses the chart/confusion/reasoning/cost helpers from `braintrust_report.py` and `load_manifest`/canonical-config handling from `score_manifest.py`. Guards against Braintrust span events whose `input` is a list, and reports expected-vs-actual cost including a prompt-caching note (cached input billed at ~10%).
- **Braintrust scorers: exact_match, failure, cost** — the Braintrust eval registers exactly three scorers: `exact_match` (exact-match accuracy), `failure` (error-sentinel rows), and `cost` (per-row actual billed USD from OpenRouter's `usage.cost`, captured by the runner and read by a code scorer — no price args needed). All three are code scorers (no LLM calls, no scorer credits). Near-miss (runner-up) is NOT a Braintrust scorer; it is computed locally by `score_manifest.py` from the `runner_up` the runner records in manifest + span metadata.
- **Local failure-rate + cost reporting in `score_manifest.py`** — the manifest now records a `cost` field per completed row (OpenRouter `usage.cost`); `score_manifest.py` reports `failure_rate`, `total_cost_usd`, `cost_coverage`, and `avg_cost_per_image_usd` in `_final.json`/`_final.md`, and backfills missing `cost` (like `runner_up`) from Braintrust span metadata (read-only fetch, no scorer credits). Guarantees failure/cost numbers are available locally even if Braintrust score/credit limits cap out.
- **Near-miss (runner-up) scoring** — `score_manifest.py` computes 1.0 when the model misclassifies but its stated runner-up label (the "Runner-up:" line the prompt forces into the reasoning trace) was the correct answer. It is a pure code parse (no LLM calls). `extract_runner_up()` lives in `src/openrouter_classifier.py`; the eval runner records `runner_up` in both the manifest and Braintrust span metadata.
- **Runner-up backfill for pre-tracking rows** — `score_manifest.py` now computes near-miss for the full run: rows recorded with a `runner_up` field count directly, and rows completed before runner-up tracking shipped are backfilled by parsing their reasoning traces from Braintrust experiment metadata (read-only fetch, no scorer credits; `--no-backfill` to skip). Final reports (`_final.json`/`_final.md`) now include near_miss count/accuracy, share-of-misses, runner-up coverage, and the near-miss row list. Backfill matches both the exact experiment name and Braintrust's version-suffixed names (`<name>-*`), and resolves config from `braintrust.env` as the source of truth even when `.env`'s stale key is already in the process env.
- **Faster experiment fetch** — `src/braintrust_utils.py` paginates `/experiment/{id}/fetch` with `limit=1000` (was 100), cutting the round-trips needed to read an experiment's spans by ~10x (validated against the API).
- `src/notify.py` — local completion sounds (macOS): a Mario-style rising C-major power-up jingle for success and a descending game-over motif for failures, synthesized with numpy and played via `afplay` (no audio assets or external packages). `play_success()` and `play_failure()` are safe to call anywhere and never raise.
- `resume_until_complete.py` — re-invokes the eval runner from its manifest checkpoint until every dataset row has a final status, so a run persists to full completion even if the Braintrust side crashes or caps out. Alerts with the failure motif on eval-process crashes and on abandonment after `--max-cycles`.
- `score_manifest.py` — computes final numbers (exact_match, per-class accuracy, error/empty counts) directly from the local manifest JSONL with **no Braintrust calls**, saving `_final.json` + `_final.md` into `reports/experiment_reports/`. Guarantees result numbers are always available even if Braintrust score/credit limits cap out.
- `run_v11_8_800_after_480.py` — eval queue script that waits for an in-flight 480-image run to complete, then runs the v11.8 prompt with qwen3.7-flash (high reasoning, 8192 max_tokens) on the 800-image `rvl_cdip_800` dataset using the `RESEARCH_FUNDING_API_KEY` OpenRouter key.
- Classification prompt `v16` (v11.9 + 2 worked examples for budget↔invoice and handwritten↔letter). Deprecated in favor of v17.
- `v16_multislice_evaluation_report.md` in `reports/` — full three-slice analysis identifying the three root causes of the drop from ~99% to ~80% exact_match.
- `eval_160_v16_v1.log`, `eval_160_v2_v16.log`, `eval_160_v3_v16.log` — raw v16 evaluation logs.
- `eval_v16_v{1,2,3}.jsonl` manifests in `reports/manifests/` for all v16 runs.

### Changed

- **Resilient eval retry loop** — `braintrust_openrouter_input.py` now: (1) fails over to the alternate OpenRouter key (`RESEARCH_FUNDING_API_KEY`) when the primary hits a quota/credit 403, (2) throttles adaptively on upstream 429s (records recent rate-limits, sleeps per `Retry-After` or an escalating 5/15/45s backoff), (3) sleeps 2s/4s for other transient errors, (4) salvages rows that fail all primary retries with one attempt through `--fallback-model` (e.g. `google/gemini-2.5-flash-lite`) — designed for content-filtered images, and (5) logs span metadata safely (never raises on Braintrust logging failure). Per-error-type backoffs are module-level constants.
- **`--fallback-model` wired through `resume_until_complete.py`** — the resume watcher passes the salvage model through to each relaunched eval cycle, and `--no-score` disables its new default auto-scoring of the manifest on completion (via `score_manifest.py`, zero Braintrust credits).
- **Completion alert sounds** — the eval runner (`braintrust_openrouter_input.py`) now plays the success jingle at the end of a run with zero failed rows and the failure motif if any row errored (catchall for failures/errors in a Braintrust run). Mute with `--no-sound`.
